# Инструкции для ИИ-ассистентов — XML Editor Reloaded

Правила и ограничения. Детали — в `PROJECT-STRUCTURE.md` (обновляйте при изменении структуры) и `REFERENCE-PROJECTS-STRUCTURE.md`.

## 📌 Контекст проекта

- **Назначение**: просмотр и редактирование XML-таблиц (TableData) мода Jagged Alliance 2 1.13; просмотр STI-изображений предметов.
- **Стек**: .NET 10, C#, WPF, SQLite (метаданные).
- **Решение**: `xml-editor-reloaded/`; все проекты и изменения — только внутри неё (кроме документации и конфигурации в корне).
- **Данные**: `References/JA 2 1.13 v4` и `v5`; таблицы — `<GameDir>\Data-1.13\TableData`, изображения — `BigItems`, `Interface`, `tilesets\0`. Редактор работает с обеими версиями и будущими наборами полей.

## 🌍 Общие правила

- **Язык общения**: русский.
- **Кодировка файлов**: UTF-8 без BOM.
- **Стиль работы**: минимальные точечные правки; не переписывайте и не рефакторите файлы без прямой просьбы.
- **Автономность**: ошибки компиляции и сборки исправляйте самостоятельно; задача завершена только при рабочей сборке.

## 🚫 Ограничения по репозиторию

- Не создавайте и не изменяйте проекты за пределами `xml-editor-reloaded/` (исключение — документация и конфигурация в корне).
- Не выполняйте `git push` без явной просьбы; локальный коммит после каждого milestone обязателен.
- Не добавляйте в git артефакты сборки (`bin/`, `obj/`), кэши IDE (`.vs/`, `.idea/`), файлы `*.user` и содержимое `References/`.

## 📚 Справочные проекты

- `References/` — только для чтения: нельзя изменять, переименовывать, переформатировать или удалять файлы; папка исключена из git и обновляется только пользователем.
- Без отдельного разрешения можно читать и анализировать `References/JA 2 1.13 Image viewer`, `References/xml-editor`, `References/JA_2_1.13_TableData_Editor`, `References/FreeImage`, `References/JA 2 1.13 v4`, `References/JA 2 1.13 v5`.

- `References/Ja 2 1.13 source` (C++, ~5,4 ГБ) — только по явному разрешению пользователя на одну задачу; разрешение не переносится дальше.
- v4/v5 используйте для чтения; проверки на запись выполняйте на копиях, а не на оригиналах в `References/`.

## 🛡 Целостность XML-данных

Главное правило: **редактор не имеет права ломать XML-файлы**.

- Никогда не удаляйте элементы, поля и колонки, включая неизвестные метаданным, DTO и модели.
- Не приводите записи к фиксированному набору колонок: записи разрежены, отсутствующие элементы остаются отсутствующими.
- Сохраняйте лексическое представление и тип: целые, дробные (`1.3`, `0.0`), строки, пустые элементы; `1.0` не превращайте в `1`, регистр не меняйте, числа пишите только в invariant culture.
- Сохраняйте структуру документа, порядок элементов, повторяющиеся элементы, регистр имён, XML-декларацию и кодировку; BOM и переводы строк сохранять необязательно; не переформатируйте файлы игры без необходимости.
- Изменяйте только явно отредактированные пользователем значения; не пересобирайте документ сериализатором целиком.
- Неизвестные элементы и атрибуты сохраняйте для обратного round-trip.
- Загрузка → сохранение без правок не должна менять содержимое; если изменений нет, файл вообще не перезаписывается.
- Ошибки XML показывайте пользователю; не исправляйте и не перезаписывайте файл автоматически.
- Валидация предупреждает, но не удаляет и не нормализует данные.
- Метаданные и модель версионно-независимы: не хардкодьте поля под v4/v5; новые поля должны сохраняться и отображаться, даже без описания.

## 🌐 Локализация

- **v4 — русская локализация, v5 — английская базовая**: отсутствие `Russian.*` в v5 — норма, а не ошибка или потеря данных.
- Оверлеи — `<Language>.<BaseFile>.xml` в `TableData` (например, `Russian.Items.xml`); это не самостоятельные таблицы и в списке таблиц не появляются.
- Оверлей содержит ключ (`uiIndex`, `mIndex`, `pIndex`, `ubIndex`, `uiSlotIndex`, `SectorGrid`) и только переопределённые поля; он может быть неполным. База даёт схему и значения по умолчанию; отсутствующее поле показывается из базы с пометкой «не переведено».
- Правка перевода пишется только в оверлей и только в затронутое поле; база не меняется. Структурные/непереводимые поля (`Enabled`, `Sector`, `popup`, `generator`) сохраняются как есть.
- Оверлеи подчиняются правилам целостности XML.
- Не создавайте оверлей копированием всей базы: только ключ и переводимые поля (плюс необходимые структурные элементы).
- Вложенные структуры требуют отдельных ключей: `CITY_INFO/CITYLIST/CITY` — по `uiIndex`; `FACILITYTYPES/FACILITYTYPE/ASSIGNMENT` — по `ubAssignmentType`; `MERCGEARLIST/MERCGEAR/GEARKIT` — по порядковому номеру набора.
- Валидация показывает недостающие, «сиротские», дублирующиеся и пустые переводы; автоматически не заполняет.
- **Локализация редактора**: UI-строки — в RESX без хардкода; минимум английский и русский; язык переключается в настройках.

## 🏗 Архитектурные правила

- Backend-библиотеки не ссылаются на WPF и не знают о GUI; зависимость направлена только от frontend к backend.
- Парсинг/сохранение XML, метаданные, декодирование STI и работа с изображениями — в backend.
- Изображения в backend — сырые пиксели (RGBA); `BitmapSource` и отображение — в WPF-слое.
- Длительные операции — асинхронно, с `CancellationToken` и отменой; UI-поток не блокировать.
- Изменяйте только файлы игры, которые пользователь явно открыл и сохранил; настройки приложения храните вне `TableData` (каталог приложения или `%AppData%`).
- Метаданные таблиц — в SQLite; схема версионируемая и не требует ручного редактирования.
- Загрузка и сохранение управляются метаданными, а не ветками кода для v4/v5: отличия версий — это данные.

## 💻 Стиль кода

- Предпочтительно MVVM: бизнес-логика и данные — не в code-behind WPF-окон.
- Не используйте `.Result` и `.Wait()` в UI-потоке.
- Публичные типы и члены backend-библиотек имеют XML-документацию.
- Не оставляйте закомментированный код и отладочные выводы.

## 📝 XML-комментарии

- Подробные, строго на английском.
- Описывайте `<param>`, `<returns>` и `<exception>`, предусмотренные контрактом.
- Для стандартного результата API описывайте `error_code`, `error_text` и `data`.
- Не дублируйте `<summary>`; удаляйте системные и ИИ-префиксы.

- После milestone и зелёных `dotnet build`/`dotnet test` — локальный коммит `Mx: …`; push — только по просьбе.
- Не редактируйте сгенерированные файлы (`obj/`, `*.g.cs`, `*.Designer.cs`).
