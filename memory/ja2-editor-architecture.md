- **Solution:** `xml-editor-reloaded/XmlEditorReloaded.slnx` (.slnx format), projects under `src/` (`Core`, `Xml`, `Data`, `Imaging` targeting `net10.0`; `App` as `net10.0-windows` WPF) and `tests/` (five xUnit projects: `Core.Tests`, `Xml.Tests`, `Data.Tests`, `Imaging.Tests`, `App.Tests`, plus the console UI-smoke runner `UiSmoke`, which is not a test project — see [[ja2-editor-ui-smoke]]). Shared `Directory.Build.props` (nullable, docs XML for src) and `.editorconfig` (utf-8). Build command and sandbox workarounds — `AGENTS.md`.
- **Packages:** xUnit 2.9.3 + Microsoft.NET.Test.Sdk; CommunityToolkit.Mvvm 8.4.0 + Microsoft.Extensions.DependencyInjection in `App`; Microsoft.Data.Sqlite 10.0.0 plus an explicit `SQLitePCLRaw.lib.e_sqlite3` 2.1.14 override to clear NU1903. Since M8 every backend project references `Microsoft.Extensions.DependencyInjection.Abstractions` 10.0.0 only (for `Add…` extensions); `Data.Tests` references the full `DependencyInjection` package and the `Xml` project for composition tests.
- **M8 wiring:** `Xml.Repository.TableRepository` implements `ITableRepository`, resolves metadata when `IsMapped`, and downgrades to document-driven mode with a `metadata.unmapped` diagnostic (also when a mapped descriptor has no metadata row). Composition is `AddXmlEditorCore()` / `AddXmlEditorData(databasePath, tableDataDirectory)` / `AddXmlEditorXml(tableDataDirectory)` / `AddXmlEditorImaging()` from each project root namespace; `FileSystemTableCatalog` and `XmlFileLookupRepository` pull languages from the metadata provider themselves, so they need no explicit language list.
- **Corpus harness:** `XER_CORPUS_DIR` + `XER_CORPUS_DUMP_DIR` env vars, copies the data to a temp dir, asserts no unmodified file is rewritten (bytes and mtime) and tolerates only `Lookup/AttachmentPoint.xml` as malformed. `Data.Tests` has a matching env-gated real-data catalogue test (expects 238 v4 / 239 v5 base tables, 25 / 0 overlays). Cross-dataset copy uses `XER_COPY_SOURCE_DIR`/`XER_COPY_TARGET_DIR`.
- **Performance gates:** `[Trait("Category","Performance")]` env-gated tests. v5 baselines: Items 1775 records 75 ms, Attachments 6023 records 27 ms, load+edit+save 380 ms, catalog 239 tables 30 ms, metadata 73 tables 32 ms; the 2 s gate is tight when the whole solution runs in parallel, so run performance tests separately.
- **Latest verification baseline (2026-11-03):** build 0 warnings/0 errors with `-warnaserror`; 600 tests green (Core 62, Data 93, Imaging 24, Xml 221, App 200); UI-smoke (81 сценарий, включая S50; в песочнице 56) зелёные; corpus v4/v5 и perf-гейты — по `PLAN.md`; no BOM; `References/` untouched.
- **Operation log (M23b8):** `Core/Diagnostics/OperationLogEntry.cs` defines `OperationLog`/`IOperationLog`; `Data/Diagnostics/FileOperationLog.cs` writes `%AppData%\XmlEditorReloaded\XmlEditorReloaded.log` (UTF-8 no BOM, one session header, UTC entries, stack in `Detail`, 4 MiB rotation to `*.1`, write failures swallowed). `App.OnStartup` installs the sink before DB migration and `OnExit` clears it; save/load/lookup/metadata/tab/catalog/copy boundaries log errors, and Dispatcher/AppDomain/unobserved-task handlers log and keep the UI alive. Unit tests must restore the previous static sink in `finally`.
- **DSH sandbox test path (2026-10-26, updated 2026-11-01):** `Directory.Build.props` sets `MSTest.EnableParentProcessQuery=false` and `NuGetAudit=false` when `DSH_SHELL`/`DSH_SESSION_ID` is present (testhost otherwise opens its parent with `PROCESS_ALL_ACCESS`, which the restricted token denies). `util-scripts/test.ps1` restores/builds with one MSBuild node, uses a per-run `.tmp/run-*` temp root (App tests would otherwise exhaust `%TEMP%\xer-app-tests`), and runs the five `*.Tests.csproj` sequentially; it deletes older `run-*` roots and its own root after success, keeping one failed root for diagnostics (`-KeepTemp` keeps a successful one too). `dotnet test <single project>.csproj` also works; the whole solution hangs. Commands and the PowerShell-policy bypass — `AGENTS.md`.
- **Artifacts output (2026-10-30):** `Directory.Build.props` sets `ArtifactsPath` to the repository-level `out/`. Reason: the DSH sandbox labels the workspace with low mandatory integrity, so an exe built inside the tree starts at low integrity, `%AppData%` writes are denied and the metadata migration fails with `SQLite error 14` (`metadata.migration_error`), writing neither the log nor the bootstrap trace; `out/` carries no label, so the exe runs at medium integrity. Run the app from `out/bin/XmlEditorReloaded.App/<Configuration>/XmlEditorReloaded.App.exe`.
- **Repository hygiene:** `.gitattributes` marks `tests/**/Fixtures/**` as `-text` so BOM/CRLF/LF fixture variants survive checkout; `.mimocode/` is git-ignored. `find References -type d -name bin -o -name obj` is **not empty** — the `bin/obj` folders belong to the vendored `References/JA 2 1.13 Image viewer` (dated 2025-10-28, shipped with the reference, not created by our builds) — scope the checklist check to `References/JA 2 1.13 v4|v5` or compare timestamps instead of treating any hit as a violation.
- **How to apply:** extend the save path with byte patching rather than serializer tweaks (see [[ja2-editor-xml-roundtrip]]). Keep `PLAN.md` status/roadmap current after each milestone; `PROJECT-STRUCTURE.md` is structural only (repository layout, projects, dependencies, data formats, build commands, conventions) and must stay free of milestone history and implementation narratives. Validate all numeric input as invariant (reject `1,5`/`1,000`) and pass cancellation tokens down to every I/O call. UI work consumes `TableWorkspace`/`IDataSetSession` rather than `TableDocument` directly. See [[ja2-editor-status]], [[ja2-editor-metadata]], [[ja2-editor-shell-grid]].
