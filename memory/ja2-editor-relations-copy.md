- **M18 relations + main-table pickers (commit `96f583a`, 2026-10-24):** migration `0007_TableRelations.sql` adds `TableRelations` (`SourceTableId`, `SourceField`, `TargetTableId`, `TargetValueField`, `TargetDisplayField`, `Kind`, `FilterField/Operator/Value`, `LabelKey`, `RemapByText`, `Ordinal`, FKs to `Tables`, unique on source/field/kind/target/value) and seeds **84** relations: 68 `Reference`, 5 `SubTable`, 7 `ChildRows`, 4 `Reverse`. Targets: `ITEM`=`Items.Items` display `szLongItemName`; `AMMO`=`Items.AmmoStrings.AmmoCaliber`; `AMMOTYPE`=`Items.AmmoTypes.name`; `Food`/`Clothes`/`RandomItem` display `szName`. `ITEMTOEXPLOSIVE` is **not a table**: it becomes `Items` filtered by `usItemClass HasFlag 768` (grenade 256 + bomb 512). 1:1 sub-tables: `Weapons` matched by item `uiIndex`; `Magazines`/`Armours`/`Explosives`/`LoadBearingEquipment` matched by item `ubClassIndex` (LBE target key is `lbeIndex`, not `uiIndex`). Four placeholder items (v4 77/161/131/428) have no `ubClassIndex` and no sub-table row — expected, tests tolerate ≤10. Legacy references owned by shopkeeper/enemy/militia/IMP/sounds are deferred to M20 because their Tables rows do not exist yet (FK). Filters use a closed operator set `Equals`/`NotEquals`/`Contains`/`HasFlag` (one predicate per relation); they **only narrow picker options** — existing values are always appended as options, and validation checks the complete unfiltered target. Core: `TableRelation`, `RelationFilter`, `RelationTarget`, `ITableRelationResolver`; `ITableMetadataProvider.GetRelationsAsync` implemented by `SqliteMetadataProvider`. `Xml.Relations.TableRelationResolver` loads targets through `TableCatalog`/`TableRepository`, caches per `(targetTable, language)` keyed by a file stamp (length+mtime of base and overlay), merges overlay display text, and supports `RelationTarget.FindValueByDisplay` remap. `Invalidate(table)` runs after a successful save. App: `RelationColumnData` + searchable `RelationPicker` (filter by display or ID, Enter commits, Escape restores, typing an unknown numeric ID is allowed and stays raw); grid uses a `DataGridTemplateColumn` with display/tooltip converters; detail panel shows the picker plus a “→” `GoToTargetCommand`. Cross-table navigation raises `TableNavigationRequested` → `MainViewModel.OpenEditorByNameAsync` + `TableEditorViewModel.SelectRecord`; same-table targets select the row directly. Validation: `TableValidator.ValidateAsync(..., relationTargetValues)` emits `validation.lookup_missing`; `TableWorkspace.ValidateAsync` passes the map through. Known limit: `DefaultAttachment` is declared a `ListField`, so it stays read-only (`IsRelation` true but no picker) until M19 list editing; `AvailableAttachmentPoint` likewise. Tests: `TableRelationsTests`, `RealRelationTests` (env-gated: every seeded Reference resolves on v4/v5, all class items covered by 1:1 sub-tables, files unchanged), `TableRelationResolverTests`, `RelationFilterTests`, `RelationColumnDataTests`, `RelationPickerTests`, editor/grid/detail/navigation tests; `MainViewModelTests.FollowRelation_*` inserts a custom relation to prove cross-table navigation.
- **M21 multi-dataset + cross-dataset copy (2026-10-24, commit `f405300`):** backend `Xml/Copy` — `ITableCopyService.PreviewAsync/ApplyAsync` with immutable plan; records are copied as `XElement` clones so sparse shapes, unknown fields, repeated elements and lexical values survive. `TableCopyConflictPolicy` `Skip/Overwrite/Merge` (merge fills absent fields only, overwrite keeps target-only fields) and `TableCopyKeyMode` `Preserve/Allocate` (allocation = max integer key + 1 per table, also used for positional/no-key tables). `TableCopyRemapper` rewrites lookup columns by lookup name and `RemapByText` relations by display text; ambiguous/not-found references keep the source value and become warnings. `SubTable`/`ChildRows` relations are optional: sub-table rows reuse the parent target key when the key field is the parent link (`Weapons`), child rows get allocated keys and the parent link is rewritten; child rows are skipped when the target already has rows for that parent. Apply reloads both sides from disk before planning, writes only dirty files with `TableFileSaver`, and restores already-replaced files from the captured original bytes if a later save fails or is cancelled. Empty base files (only `xml.record_element_missing`) become insertable via internal `TableDocument.TryEnableEditing`/`InsertRecord`; the source document is never saved. App: `MainViewModel` has a `DataDirectories` selector (settings + recent, recent-first), `SelectedDataDirectory`, activation without closing tabs, `DatasetLabel`/`TableDataDirectory` on `IEditorTab`, tabs keyed by both fields, `TableNavigationRequest` carries the owning directory, `SelectedRecordKey` and `ReloadAsync` were added to `IEditorTab`; clean target tabs reload after a copy, dirty ones are counted and reported. `TableCopyViewModel`/`TableCopyWindow`/`WpfTableCopyDialogService` provide source/target combos with browse, common-table intersection, optional key filter (blank = all), policy/key-mode/related options, preview grid (action, remaps, related rows, warnings) and apply; all strings in RESX en/ru. `DatasetNames.LabelFor` uses the game root (parent of `Data-1.13`) so v4/v5 labels differ. Tests: `TableCopyServiceTests` (7), `TableCopyViewModelTests` (4), `DataDirectoryItemTests`, multi-dataset/copy tests in `MainViewModelTests`, and env-gated `CorpusCopyTests` (`XER_COPY_SOURCE_DIR`/`XER_COPY_TARGET_DIR`) that copies a v4 weapon item into v5 with allocated keys, validates Weapon/Attachments and `ubCalibre` remap via `AmmoStrings`, and hashes the source. Known limits: copy reads on-disk base tables only — unsaved tab edits and overlay translations are not copied; composite/positional keys need explicit key text; related child rows are skipped if the target already has rows for the parent; the 2 s perf gate is tight when the whole solution runs in parallel (run performance tests separately).
- **M23b8 lookup comparison fallback (2026-10-27):** migration `0017_CopyComparisonFields.sql` sets `ColumnFlags.ComparisonField` (`1 << 2 = 4`) on `name` for all 23 `IsLookup = 1` tables with an idempotent `Flags | 4` upsert that preserves other hint data. `TableCopyService.ResolveComparisonField` reads the hint (then declared columns) and ignores a field that is part of the key. When the source key is absent from the target, `FindComparisonMatches` compares the raw field value ordinally (no trim/case folding); a single match becomes the target row, so `Skip` skips it, `Overwrite` rewrites it and `Merge` fills only its absent fields, always keeping the target row's own key (`TargetKey`/related rows use it). The search also runs in `Allocate` mode, matching legacy `AlternateRowSearch` so no copy path can create a duplicate display name. More than one match adds the row and emits a deduplicated warning into `TableCopyResult.Warnings`. Legacy divergence: a matched key stays authoritative when the name differs (legacy added a name twin), and ambiguity adds instead of taking the first row. See report `L-OPS-011` and `M23A-PARITY/56-m23b8-implementation-log.md`.
