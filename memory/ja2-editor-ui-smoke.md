- **Что это:** консольный проект `xml-editor-reloaded/tests/XmlEditorReloaded.UiSmoke` (`net10.0-windows`, UI Automation + `SendInput`). Запускает настоящий `XmlEditorReloaded.App.exe`, проходит сценарии из `M23A-PARITY/MANUAL-SMOKE-CHECKLIST.md`, сверяет тексты с RESX и пишет `report.md`/`report.json`. В solution добавлен 2026-10-31; тестовым проектом не считается (`test.ps1` берёт только `*.Tests.csproj`).
- **Покрыто (2026-10-31, зелёные):** S01 холодный старт, S02 добавление v4, S03 переключение датасета с открытыми вкладками и несохранённой правкой, S05 детали/диагностика, S06 generic-таблица и переключение датасета, S07 поиск, S08 фильтры (условия AND/OR, фильтр по значению из контекстного меню, сброс, несохранённая правка не теряется), S09 массовая правка трёх выделенных строк (сводка, предпросмотр, undo/redo), S10 строки `Lookup.Cursor` (добавление, дублирование, удаление с подтверждением, undo; для составного ключа `Items.Attachments` «Дублировать» отключена — L-OPS-009), S11 колонки/layout (поиск и флажки, «Все»/«По умолчанию»/«Сбросить раскладку», ширина, порядок, сортировка, повторное открытие, `layouts.json`), S12 сохранение грязной вкладки, S13 закрытие вкладки (три ветки диалога), S14 «Сохранить всё» и закрытие приложения (Cancel/Save, чистая вкладка не спрашивается), S48 повреждённый v5-файл, S50 целостность `References/` (SHA-256 до/после). 2026-10-31 добавлены части B–D: S15–S21 и S23–S25 (item workspace: мастер-деталь, поиск/переход, 27 вложений, правка полей и undo, подтаблицы по классу, child rows с relation picker, вложенные структуры с сохранением и переоткрытием, русский оверлей, непереведённый item 1742, new/duplicate/delete/change ID и create+undo на v5), S26–S29 (merc gear: рабочее место, комплекты и лимит 80 символов, слоты/pickers/цены и валидация без clamp, русский оверлей), S30–S32 (shopkeeper v5: строка дилера, правка количества с переоткрытием, дубликат `uiIndex=26`). Ручными остаются S04 (диалог выбора папки), S22, S71–S75, S82, S83 (зрение/рабочий стол).
- **Запуск:** сначала сборка, затем `out/bin/XmlEditorReloaded.UiSmoke/debug/XmlEditorReloaded.UiSmoke.exe [--only S01,S12] [--work .tmp/ui-smoke/run] [--lang ru] [--list] [--keep]`. Нужен интерактивный рабочий стол: раннер переводит окно приложения на передний план и шлёт настоящие клики/клавиши. Сценарии с записью копируют `TableData`, `BigItems`, `Interface`, `tilesets` во временный каталог сценария; оригиналы в `References/` не трогаются.
- **Изоляция:** `XER_APP_DATA` (см. `AppPaths` в `Data/Settings`) перенаправляет `settings.json`, `layouts.json`, `metadata.sqlite` и лог в каталог сценария; `UiApp.Start` пишет туда стартовые настройки. `UiStrings` читает `Strings.resx` + `Strings.<lang>.resx` напрямую, чтобы проверять те же тексты, что показывает UI.
- **Грабли, уже учтённые в коде:**
  - модальный диалог: `InvokePattern.Invoke` не возвращается, пока диалог открыт → кнопку закрытия вкладки вызывают через `Task.Run`, а диалог обрабатывают в основном потоке;
  - синтетические клики попадают в окно, которое оказалось сверху (терминал агента) → `UiApp.Start` держит окно приложения topmost (`NativeInput.KeepOnTop`); перед вводом `EnsureForeground`/`Activate` поднимают владельца элемента (`AttachThreadInput` + `SetForegroundWindow`), а если foreground-лок не пускает — временно обнуляют `SPI_GETFOREGROUNDLOCKTIMEOUT` и кликают по заголовку окна;
  - редактирование ячейки надёжнее клавиатурой (`cell.SetFocus()`, F2, Ctrl+A, ввод, Enter), чем двойным щелчком;
  - изменение ширины колонки — drag правого края заголовка (`DragRightEdge`), перестановка — drag в **левую четверть** целевого заголовка: центр даёт вставку после, то есть для соседней колонки ничего не меняет;
  - после перестановки UIA-дерево сохраняет порядок создания колонок, а меняются только экранные координаты → порядок проверяется сортировкой заголовков по `BoundingRectangle.Left`, а не порядком обхода;
  - заголовки грида виртуализированы и реализуются не обязательно непрерывным префиксом → в S11 сверяются первые пять заголовков, счётчик «Колонок: N из M» и `layouts.json`;
  - `layouts.json` создаётся только при первом изменении раскладки, а не при открытии таблицы → S11 сначала нажимает «По умолчанию», чтобы получить сохранённый baseline;
  - `uiIndex` в `Items.Weapons` — глобальные индексы предметов (0…1775, с пропусками), а не 0…388 → ожидаемые концы сортировки S11 читает из XML;
  - дамп UIA надо снимать до закрытия приложения (иначе окон уже нет) — закрытие перенесено в `finally` после `DumpUi`;
  - `ValidationList` живёт в свёрнутом Expander (для повреждённого файла пуст) → ошибку разбора читают из `DiagnosticsList` в «Деталях»;
  - шаблон `name.*` в `Directory.GetFiles` матчит и сам файл → `ScenarioUi.BackupCopies`;
  - `StatusError` — формат `«Ошибка: {0}»` → сравнивать префикс через `ScenarioUi.FormatPrefix`;
  - AutomationId задаётся через `AutomationProperties.AutomationId` или `x:Name` (диалоги `UnsavedChangesWindow`/`ExternalChangeWindow`).
  - вкладка WPF TabControl отдаёт содержимое выбранной вкладки дочерними элементами `TabItem`, поэтому `WorkspaceUi.TabText` берёт только `Text` внутри рамки заголовка, иначе подпись раздела «Вложения — Строк: 27» тонет в текстах грида;
  - у вкладок мастер-деталей UIA `Name` — имя типа view model, а не таблицы → `ScenarioUi.CloseActiveEditorTab` закрывает первую вкладку по кнопке `✕`, `CloseTab("Items.Items")` их не находит;
  - у data-bound `ComboBox` UIA `Name` пустое или равно имени типа → выбранный текст читает `Ui.ReadComboSelection` из раскрытого списка; после выбора popup может закрыться сам, и `Collapse`/`Select` кидают `ElementNotEnabledException: Could not open the process token` — это штатное завершение, а не ошибка;
  - relation picker коммитит только по `Enter`, фильтрует по отображаемому тексту (`szLongItemName`) → вводят имя («Gun Barrel Extender»), а не ID; у item 37 «Combat Knife» нет флага `Attachment`, поэтому в picker вложений item 12 он не попадает;
  - вложенные поля (`STAND_MODIFIERS/FlatBase`) доступны только после `ExpandAll(ItemTabs)`, а `ItemFieldFilterBox` существует только на вкладке «Поля»;
  - счётчик строк child-раздела («Вложения — Строк: N») обновляется по `Editor.Rows.CollectionChanged`; без этого после добавления/удаления строки он отставал на одно изменение (дефект найден и исправлен в `ItemChildSectionViewModel`);
  - в shopkeeper-вкладке имя торговца — из имени файла: `AdditionalDealer_43_` и `Tony` (не `TonyInventory`); правка дубликата `uiIndex=26` адресуется строкой, а не ключом, иначе уходит в чужую запись.
