## F0. Undo/Redo: сохранить идентичность элемента (S10)

**Проблема.** `ElementSnapshotState.Apply` заменяет `XElement` новым клоном, а более старые
снимки продолжают ссылаться на старый объект. После `Undo` правки имени добавленная запись
становится «сиротой»: следующий `Undo` не может её удалить, а `Redo` вставляет второй экземпляр
с тем же ключом. Воспроизведено тестом: add → edit name → undo ×2 → `CanUndo == false`, но
запись с ключом `2` остаётся; redo → две записи с ключом `2`, одна с пустым именем.

**Изменения.**
- `ElementSnapshotState` хранит отсоединённый элемент и при восстановлении переиспользует его,
  а не создаёт новый.
- `Undo`/`Redo` меняют содержимое существующего элемента на месте (`ReplaceAttributes`,
  `ReplaceNodes` с клонированием узлов), затем при необходимости переставляют его в исходную
  позицию.
- `MarkRemoved` больше не обнуляет `Current`: удалённый элемент нужен для восстановления и
  повторного удаления.
- Позиция восстановления: предыдущий/следующий узел, если он ещё в документе; иначе индекс
  среди элементов родителя.

**Файлы.** `src/XmlEditorReloaded.Xml/Workspace/TableEditHistory.cs`,
`tests/XmlEditorReloaded.Xml.Tests/UndoAndBulkTests.cs` (или отдельный файл тестов истории).

**Тесты.**
- add → edit → undo ×2: запись удалена, `CanUndo == false`, `CanRedo == true`.
- add → edit → undo ×2 → redo ×2: ровно одна запись с исходным ключом, имя восстановлено.
- add → edit → duplicate → delete → undo до конца → redo до конца: количество записей, порядок
  и уникальность ключей совпадают с ожидаемыми на каждом шаге.
- undo удаления соседней записи не меняет ключи и порядок остальных.

**Критерий готовности.** Ни один сценарий Undo/Redo не создаёт дубль ключа и не оставляет
запись после отмены её добавления; `CanUndo`/`CanRedo` соответствуют фактическому состоянию;
build и все тесты зелёные; XML после полного undo/redo побайтно соответствует ожидаемому
(в тестах — структурно, с сохранением лексических значений).

**Статус:** выполнено 2026-10-30. `ElementSnapshotState` восстанавливает содержимое на месте и
переиспользует отсоединённый `XElement`; `MarkRemoved` сохраняет объект для повторного
подключения. Добавлены тесты `UndoRedo_AddThenEdit_RemovesRowAndRestoresItOnce` и
`UndoRedo_AddEditDuplicateDelete_RestoresUniqueRowSequence`; полный прогон — 566 тестов, 0
ошибок.

## F1. Вложенные таблицы и контекстное меню (S06, S08)

### F1.1. Колонки `Map.Cities` (S06)

**Проблема.** `TableDocument` собирает только прямых детей корня (`CITY_INFO → CITY`), поэтому
для ключа `CITYLIST/CITY` его `Records` пуст. Строки приходят через `OverlayMerger` (отсюда
верное количество), а `TableSchemaBuilder` смотрит на `TableDocument.Records` и получает ноль
колонок.

**Изменения.**
- `TableSchemaBuilder` для метаданных с вложенным ключом собирает элементы записей по
  объявленному пути (`RecordKey.Primary.Path`) и строит колонки по их прямым дочерним полям.
- Вложенные элементы (`baseSector`, `townPoint`, `iconPosition`) остаются отдельными колонками
  типа `Nested` либо скрываются до появления nested-редактора; решение фиксируется в коде и
  тесте, чтобы не показывать пустые «псевдоколонки».
- Строки без базовой записи (`WorkspaceRow.Record == null`) помечаются read-only на уровне
  строки/сетки, чтобы клик по ячейке не приводил к `key.not_found`. Полноценное редактирование
  вложенных записей — отдельный milestone M24a, в F1 не входит.

**Тесты.**
- Загрузка `Map/Cities.xml` с метаданными Cities: количество строк совпадает с количеством
  `CITY`, колонки `uiIndex` и `townName` присутствуют, значения читаются.
- Пустая вложенная таблица по-прежнему не declares-ит hints (существующий тест
  `Build_EmptyNestedTable_DoesNotDeclareHintColumns`).
- Попытка редактирования вложенной строки возвращает понятную ошибку/блокируется, а не
  `key.not_found`.

### F1.2. Контекстное меню при `SelectionUnit=FullRow` (S08)

**Проблема.** `TableView.OnPreviewMouseRightButtonDown` присваивает `cell.IsSelected = true`.
Если строка уже выделена, WPF пытается добавить ячейку в `SelectedCells` и бросает
`InvalidOperationException`; в логе семь таких падений.

**Изменения.**
- Убрать `cell.IsSelected`.
- Выделять строку через `SelectedItem`/`SelectedItems`, сохраняя multi-select: если строка уже
  выделена — не менять набор; если нет — при правом клике без Ctrl выделить только её.
- `CurrentCellField` и `cell.Focus()` устанавливать без изменения `SelectedCells`.

**Тесты.** UI-тест на WPF-сетку в текущем наборе может быть недоступен; минимум — проверить
отсутствие `IsSelected` в обработчике и покрыть view-model часть (`CurrentCellField`,
`CanFilterByValue`) unit-тестами. Ручная проверка: правый клик по уже выделенной строке не
показывает MessageBox и не меняет выделение.

**Статус:** выполнено 2026-10-30. `TableSchemaBuilder` собирает записи по объявленному
`RecordKey.Primary.Path`, поэтому `Map.Cities` получает колонки `uiIndex`, `townName` и остальные
поля `CITY`. Вложенные элементы (`baseSector`, `townPoint`, `iconPosition`) остаются в схеме и в
деталях, но скрыты в сетке по умолчанию до появления nested-редактора (M24a); строки без базовой
записи read-only — сетка отменяет `BeginningEdit`, а `SetCellValue` возвращает понятный статус
вместо `key.not_found`. Контекстное меню выделяет строку через `SelectedItem`/`SelectedItems`
(с Ctrl — добавляет, без Ctrl — заменяет; уже выделенную строку не трогает) и не присваивает
`DataGridCell.IsSelected`. Добавлены тесты `Build_NestedRecordPath_DiscoversColumnsFromDeclaredPath`,
`Build_NestedRecordField_IsHiddenNestedColumn`, `NestedCityTable_ShowsRowsAndColumnsAndStaysReadOnly`
и `View_RightClickSelectsRowWithoutTouchingCellSelection`; полный прогон — 570 тестов, 0 ошибок.

## F2. Статусы датасета и поиска (S04, S07)

### F2.1. Неверный каталог (S04)

**Проблема.** `BrowseAsync` меняет `DataDirectory` до валидации; `ActivateDataDirectoryAsync`
снимает `previousDirectory` уже после этого изменения и при ошибке восстанавливает неверный
путь. Если корректная папка совпадает с уже активным датасетом, ранний выход не обновляет
`StatusText`, и сообщение «В выбранной папке нет TableData…» остаётся.

**Изменения.**
- Не мутировать `DataDirectory` в `BrowseAsync` и обработчике выбора датасета до успешной
  активации; передавать путь в `ActivateDataDirectoryAsync` явно.
- Снимать `previousDirectory` из фактического текущего состояния (`SelectedDataDirectory` /
  активный датасет) до любых изменений.
- В ветке «выбранный путь уже активен» явно выставлять `StatusTablesLoaded` и очищать старую
  ошибку; при необходимости перечитывать список таблиц.
- После неудачной активации `DataDirectory` и выбранный элемент списка должны указывать на
  прежний валидный датасет.

**Тесты.** View-model тест: неверный путь → корректный путь того же активного датасета →
`StatusText` содержит «Загружено таблиц», `DataDirectory` валиден. Повторить для другого
датасета.

### F2.2. «Нет записей по запросу» (S07)

**Проблема.** `ApplyRowView` выставляет `EditorNoMatches`, но никогда его не снимает.

**Изменения.**
- Хранить признак «показан no-match»; при следующем применении фильтра/поиска, если совпадения
  есть или строка поиска пуста, восстанавливать обычный статус (или очищать его).
- Не затирать этим другие статусы (ошибки, сохранение), если они были выставлены позже.

**Тесты.** Search text A (0 совпадений) → очистка → статус не «Нет записей»; Search text B
(есть совпадения) → статус не «Нет записей»; счётчик записей корректен.

### F2.3. Компоновка поиска (S07, замечание)

- Перенести `SearchLabel` + `TextBox` в левую группу шапки, сразу после `RecordCountText`, чтобы
  поиск и «Записей: X из Y» читались вместе; правый блок шапки убрать.
- Проверить, что при узком окне элементы не наезжают друг на друга (WrapPanel/Grid).

**Статус:** выполнено 2026-10-30. `BrowseAsync` и обработчик выбора датасета больше не меняют
`DataDirectory`/`SelectedDataDirectory` до успешной активации, а снимок прежнего состояния берётся
из фактического активного каталога. Ветка «выбранный путь уже активен» явно выставляет
`StatusTablesLoaded` и тем самым снимает старую ошибку. `ApplyRowView` хранит признак показанного
no-match и снимает его, когда совпадения появились или строка поиска очищена, не затирая более
поздний статус (ошибку, сохранение). `SearchLabel` и поле поиска перенесены в левую группу
заголовка сразу после счётчика записей, а `WrapPanel` разрешает перенос элементов в узком окне.
Добавлены тесты `Browse_RejectedFolderThenActiveDirectory_RestoresLoadedStatus`,
`SelectDataDirectory_RejectedPathRestoresPreviousDataSet` и
`Search_NoMatchesStatusClearsWhenRowsReturn`; полный прогон — 573 теста, 0 ошибок.

## F3. Среда, запуск и управление датасетами (S11, S12, S01, S03)

### F3.1. `io.access_denied` (S11, S12)

**Проблема.** `File.Move(temp, target, overwrite: true)` отдаёт `UnauthorizedAccessException` не
только при ACL, но и при read-only/заблокированном целевой файле; приложение показывает общий
`io.access_denied` без пути и причины. В текущем окружении конфиги/лог созданы elevated-запуском
(владелец `BUILTIN\Администраторы`), а в корне рабочей папки есть нестандартные ACE, включая
`Everyone: Deny DeleteSubdirectoriesAndFiles`. Это делает ручной smoke невоспроизводимым.

**Изменения.**
- Preflight при старте: проверить запись в `%AppData%\XmlEditorReloaded` (пробный файл),
  залогировать пользователя, факт elevation, путь, атрибуты/владельца целевого файла.
- В сообщениях `io.access_denied` указывать путь и различать: read-only, ACL, файл занят
  другим процессом (по `IOException`/`UnauthorizedAccessException` и `FileInfo`).
- Не пытаться молча менять ACL/атрибуты игровых файлов; предлагать пользователю понятный следующий шаг.
- Проверить сценарий на чистом неэлевированном профиле и копиях вне рабочей папки; elevated-запуск
  не рекомендуется и не должен быть обязательным.

**Критерий.** При реальном ACL-запрете пользователь видит путь и причину; при read-only/занятом
файле — соответствующую подсказку; штатный запуск без администратора не требует elevation.

### F3.2. Холодный старт (S01)

- Добавить bootstrap-запись в `%TEMP%` до инициализации DI/лога, чтобы падение до создания
  `%AppData%`-лога было видно.
- Проверить ярлык/манифест на «Run as administrator»; в коде требования elevation нет.
- При фатальной ошибке миграции/доступа показывать путь и тип ошибки, а не только `Message`.

### F3.3. Удаление датасета из списка (S03)

- Добавить команду «Убрать каталог из списка» (не удалять файлы) с подтверждением.
- Запрещать удаление датасета, пока открыты его вкладки; либо предлагать закрыть их.
- Сохранять обновлённый список в `settings.json`; активным делать предыдущий валидный датасет.

**Статус:** выполнено 2026-10-30.

- **F3.1.** В `Core.Diagnostics` добавлен `FileAccessFailure`: сбой записи классифицируется как
  read-only файл, запрет Windows-разрешений (ACL) или файл, занятый другим процессом (sharing/lock
  violation по `IOException.HResult`), и превращается в сообщение с путём и следующим шагом.
  Он используется в сохранении таблиц (`TableFileSaver`), создании оверлеев, записи `settings.json`,
  `layouts.json` и миграции метабазы; sharing violation теперь отдаётся как `io.access_denied`, а не
  `io.error`. Атрибуты и ACL не изменяются.
- **F3.1/F3.2.** Preflight при старте (`StartupDiagnostics`) создаёт и удаляет пробный файл в
  `%AppData%\XmlEditorReloaded`, логирует пользователя, факт elevation, каталоги, а также
  существование, размер, атрибуты и владельца лога, настроек, layouts и метабазы. `StartupTrace`
  пишет bootstrap-строки в `%TEMP%\XmlEditorReloaded-bootstrap.log` до создания DI и основного лога;
  фатальные ошибки старта и миграции показывают код, путь, тип исключения и ссылку на трассу.
  Манифеста с `requestedExecutionLevel` в приложении нет, поэтому запуск идёт asInvoker и elevation
  не требуется; `elevated = yes` в логе сразу показывает отклонение от штатного профиля.
- **F3.3.** В шапке появилась кнопка «Убрать» для выбранного каталога: подтверждение, запрет при
  открытых вкладках этого датасета, обновление списка в `settings.json`. Если убирается активный
  каталог, активируется ближайший оставшийся валидный (сначала предыдущий, затем следующий); если
  валидных больше нет, shell очищается до состояния «каталог не выбран». Файлы на диске не удаляются.
- **Тесты.** `FileAccessFailureTests` (5), `StartupDiagnosticsTests` (6), `StartupTraceTests` (3),
  `Save_ReadOnlyTargetFile_ReportsAccessDeniedWithPathAndCause`, `RemoveDataDirectory_*` (5); полный
  прогон — 593 теста, 0 ошибок. Ручная перепроверка S01, S03, S11 и S12 входит в повторный smoke.

## F8. Обновление галочек колонок (S11)

`SetProperty(ref _isVisible, visible)`. Атрибут `[CallerMemberName]` подставлял имя
**`SetVisibleWithoutNotification`**, поэтому `PropertyChanged` приходил не с `IsVisible`. Привязка
`CheckBox.IsChecked` не обновлялась и ждала пересоздания контейнера при прокрутке; данные и
`VisibleColumns` при этом были верны.

**Изменения.** В `SetProperty` явно передаётся `nameof(IsVisible)`. Поведение «без сохранения
layout» сохранено: колбэк `_visibilityChanged` по-прежнему не вызывается.

**Тесты.** `ColumnVisibility_UpdatesVisibleColumns` расширен: после «Все» проверяются и
`IsVisible == true`, и факт `PropertyChanged` с именем `IsVisible`.

**Статус:** выполнено 2026-10-30.
