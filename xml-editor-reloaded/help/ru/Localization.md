# Оверлеи локализации

Языковые оверлеи — это файлы `<Language>.<BaseFile>.xml` в `TableData` (например,
`Map/Russian.Cities.xml`). Они не являются отдельными таблицами и не появляются в `INDEX.md`.

## Правила

- Оверлей содержит ключ (`uiIndex`, `mIndex`, `pIndex`, `ubIndex`, `uiSlotIndex`,
  `SectorGrid`) и только те поля, которые он переопределяет.
- Базовая таблица задаёт схему и значения по умолчанию; отсутствующее поле показывается из
  базы с пометкой «не переведено».
- Правка перевода записывает в оверлей только затронутое поле; базовый файл никогда не
  меняется.
- Структурные и непереводимые поля (`Enabled`, `Sector`, `popup`, `generator`, числовые
  характеристики) остаются в базе.
- Оверлей может быть неполным; валидация сообщает о недостающих, «сиротских», дублирующихся
  и пустых переводах, но никогда не заполняет их автоматически.
- Вложенным структурам нужны собственные ключи: `CITY_INFO/CITYLIST/CITY` — по `uiIndex`,
  `FACILITYTYPES/FACILITYTYPE/ASSIGNMENT` — по `ubAssignmentType`,
  `MERCGEARLIST/MERCGEAR/GEARKIT` — по порядковому номеру набора.

## v4 и v5

- v4 локализована на русский; v5 — английская база. Отсутствие `Russian.*` в v5 — норма.
- Редактор работает с обоими наборами данных; язык интерфейса не зависит от языка данных.

## В документах таблиц

Страница таблицы перечисляет только поля, которые могут встречаться в оверлее, в разделе
`## Localization`. Сами файлы оверлеев по одному не документируются; эта страница — общий
справочник.

Текущие документы таблиц перечисляют переводимые поля в разделе `## Localization`. Типичные
примеры — названия городов, названия объектов и подсказки, темы и тексты писем, строки истории
и отображаемые имена врагов/ополчения. Числовые идентификаторы, координаты, флаги, значения
матриц и прочие структурные данные остаются в базовой таблице. Оверлей перевода может быть
неполным; редактор показывает базовое значение для любого отсутствующего перевода.
