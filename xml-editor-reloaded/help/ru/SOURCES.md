# Источники и доказательства

Документы справки описывают **поставляемые игровые данные** и **игровой код, который их
читает**. Они не ссылаются на исходные файлы и номера строк: они меняются, а моддеру нужно
поведение, а не местоположение. Для каждого поля указано, какие доказательства его
подтверждают и насколько ответ достоверен.

## Типы источников

| Источник | Для чего используется |
|---|---|
| Игровой код | разбор, значения по умолчанию, ограничение диапазона, фактический тип и использование во время выполнения |
| Комментарии XML и readme | замысел автора, единицы измерения и перечисления |
| Метаданные редактора | типы, имена справочников, пределы и связи таблиц |
| Устаревшие редакторы и DTO | только имена и группировка; не смысл |
| Данные таблиц | примеры и выявление разреженных полей; не источник авторитетных диапазонов |

`References/` доступна только для чтения. Инструменты справки читают v4, v5, игровой исходный
код и устаревшие редакторы, но никогда в них не пишут.

## Корневые каталоги

| Каталог | Содержимое | Использование |
|---|---|---|
| `References/JA 2 1.13 v5/Data-1.13/TableData` | Английские базовые данные | основной набор данных |
| `References/JA 2 1.13 v4/Data-1.13/TableData` | Данные с русским оформлением и оверлеи `Russian.*` | перекрёстная проверка и запасной вариант |

## Как проверяется поле

1. Найдите корневой элемент таблицы и элементы записей в XML.
2. Найдите в игровом коде загрузчик для этих элементов.
3. Прочитайте обработчики как начального, так и конечного элемента. Путь сохранения/записи
   часто даёт лучший полный список полей, но он может записывать значения по умолчанию,
   которые загрузчик никогда не читает.
4. Сверьтесь с записью или структурой времени выполнения, которая принимает значение.
   Комментарии там часто указывают единицы измерения и диапазоны.
5. Сравнивайте данные v4 и v5, когда значения различаются; различия структуры описаны в
   разделе `Versions` таблицы.
6. Предпочитайте прямое наблюдение источника правдоподобному имени. Если смысл всё ещё
   неясен, пометьте поле как `unknown` и запишите открытый вопрос.

Тег таблицы и запись времени выполнения — устойчивые ориентиры. Имена файлов и номера строк
в справке не используются.

## Порядок доказательств

1. **Игровой код** — авторитетен для разбора, значений по умолчанию, ограничения диапазона и
   фактического типа.
2. **Комментарии XML и файлы readme** — замысел автора; проверяйте по поведению кода.
3. **Проверенные метаданные редактора** — типы, имена справочников, пределы и связи. Они
   курируются, но неполны: у некоторых таблиц нет строки метаданных.
4. **Устаревшие редакторы и DTO** — только имена и группировка; не копируйте смысл.
5. **Статистика данных** — полезна для выявления выбросов и разреженных полей; никогда не
   используется как документированный диапазон или доказательство смысла.

## Что говорит запись поля

Каждая запись поля отвечает на вопросы:

- Что хранится (единица, масштаб, индекс или битовая маска)?
- Кто это читает (загрузчик, ИИ, интерфейс, другая таблица)?
- Какие пределы задаёт код или тип поля и каково значение по умолчанию?
- Что происходит при отсутствующем, пустом или выходящем за диапазон значении?
- К каким версиям относится ответ?
- Насколько ответ достоверен и почему?

Строка `Source` использует общую метку, например `game code (item loader)`, `table data` или
`editor metadata`. Она никогда не содержит имя исходного файла или номер строки.

Если поле непрозрачно, запишите `unknown` и точный вопрос в `## Open questions`.
Правдоподобная догадка хуже задокументированного пробела.
