## Purpose

`Merchants.xml` задаёт личность дилера, деньги, множители покупки и продажи, рост `coolness`, ежедневное пополнение, задержки поставки и флаги доступности. Каждый файл `*Inventory.xml` перечисляет предметы и целевые количества для одного дилера. 80 файлов инвентаря дилеров привязаны к дилерам в коде инициализации игры: по одному фиксированному имени файла на каждое значение `ARMS_DEALER_*` плюс `AdditionalDealer_N` для дополнительных дилеров, поэтому дилер файла определяется его именем, а не каким-либо значением внутри него. Слоты `0..19` — именованные продавцы в порядке перечисления, а слоты `20..79` — слоты дополнительных дилеров, используемые городскими магазинами и обычными дилерами; поставляемая таблица заполняет слоты до `68`, а массив заполнен нулями, поэтому остальные слоты сохраняют нулевые данные торговца.

Загрузчик инвентаря также понимает более старый блок `<CONTROL>`, который задаёт те же поля торговца для дилера, к которому относится. Ни один поставляемый `*Inventory.xml` его не содержит; поскольку файлы инвентаря разбираются после `Merchants.xml`, такой блок перезаписал бы значения торговца этого дилера.

## Fields

### `MERCHANTSLIST/MERCHANT/uiIndex`

- **Type:** `Integer` (`UINT16`)
- **Description:** Слот торговца в массиве игры `armsDealerInfo`. Загрузчик записывает запись в `armsDealerInfo[uiIndex]`, и этот номер слота одновременно является значением `ARMS_DEALER_*`, которое выбирает файл `*Inventory.xml` дилера.
- **Values:** `0..79` (`NUM_ARMS_DEALERS` равно 80); запись с большим `uiIndex` молча отбрасывается.
- **Default:** `0`, если элемент отсутствует, поэтому запись без индекса перезаписывает слот 0.
- **Source:** game code (the merchant loader; the dealer enum and its count).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/szName`

- **Type:** `String`
- **Description:** Информационная метка строки, например `Tony` или `additional dealer 3`. Загрузчик читает элемент и отбрасывает его (ветвь разбора для `szName` помечена как «not needed, but it's there for informational purposes»), а комментарии структуры говорят, что имя «used in xml, not used ingame». Игра показывает имя продавца из профиля NPC.
- **Values:** Свободный текст; он не попадает в состояние игры.
- **Default:** Отсутствует; ни на что не влияет.
- **Source:** game code (the merchant loader's `szName` branch and the field comment).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/ubShopKeeperID`

- **Type:** `Integer` (`UINT8`)
- **Description:** ID профиля NPC продавца из перечисления `NPCIDs`, которое цитирует комментарий XML.
- **Numeric semantics:** Ссылка на профиль, а не индекс в этой таблице. Поставляемая таблица использует `255` для обычных дополнительных дилеров и `200` для строк городских магазинов.
- **Values:** `0..255`. Загрузчик `Merchants.xml` сохраняет значение без проверки диапазона; проверка `NUM_PROFILES` есть только в устаревшем блоке `CONTROL` файла `*Inventory.xml`.
- **Default:** `0`, если элемент отсутствует.
- **Source:** game code (the merchant loader; the inventory loader for the legacy check); table data.
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/ubTypeOfArmsDealer`

- **Type:** `Integer` (`UINT8`) — an enum, not a free number.
- **Description:** Поведение дилера: `0` покупает и продаёт, `1` только продаёт, `2` только покупает, `3` ремонтирует.
- **Numeric semantics:** Загрузчик ограничивает значение через `min(ARMS_DEALER_REPAIRS, value)`, поэтому сохраняются только `0..3`; большее значение, а также отрицательное (оно переходит через приведение к `UINT8`), становится `3`.
- **Values:** `0..3` после ограничения.
- **Default:** `0`, если элемент отсутствует, что означает «покупает и продаёт».
- **Source:** game code (the merchant-loader clamp and the dealer-type enum); table XML comment.
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/uiFlags`

- **Type:** `Flags` (`UINT32`)
- **Description:** Упакованная битовая маска флагов торговца. Каждый бит включает определённое поведение дилера.
- **Numeric semantics:** Битовая маска; биты объединяются через OR. Большее число не означает просто «больше». Разбор идёт с преобразованием по основанию 0, поэтому принимаются и поставляемые десятичные значения, и шестнадцатеричные формы `0x`.
- **Values:** `0x08000000` — только использованные предметы, `0x10000000` — даёт сдачу, `0x20000000` — принимает подарки, `0x40000000` — некоторые использованные предметы, `0x80000000` — нет инвентаря. Структура дилера определяет и другие биты классов предметов, но обычно они задаются не в `Merchants.xml`.
- **Default:** `0`, если элемент отсутствует, то есть флагов нет.
- **Source:** game code (the merchant flag constants and the merchant loader); table XML comment.
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/iInitialCash`

- **Type:** `Integer` (`INT32`)
- **Description:** Деньги, с которыми торговец начинает. Игра также сбрасывает деньги дилера к этой сумме при повторной инициализации.
- **Numeric semantics:** Деньги в целых единицах; больше — богаче. В загрузчике `Merchants.xml` ограничения нет (устаревший блок `CONTROL` ограничивает свой `<INITIAL>` диапазоном `0..1000000`), а отрицательное значение сохраняется, но не имеет смысла.
- **Values:** Деньги.
- **Default:** `0`, если элемент отсутствует, потому что каждая запись обнуляется перед разбором.
- **Source:** game code (the merchant loader; the dealer initialisation).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/dBuyModifier`

- **Type:** `Decimal` (`FLOAT`) — a 32-bit float in game code.
- **Description:** Множитель, применяемый когда торговец покупает у игрока; `0.75` платит 75% стоимости, `1.0` платит полную стоимость. У дилера-ремонтника (`ubTypeOfArmsDealer` `3`) в том же месте хранится `dRepairSpeed`, и значение масштабирует время ремонта.
- **Numeric semantics:** Загрузчик ограничивает значение диапазоном `0.1..5.0` (`min(5.0f, max(0.1f, value))`), поэтому значение вне диапазона подтягивается к ближайшей границе, а не отклоняется. Больше — лучше цена для игрока.
- **Values:** `0.1..5.0` после ограничения.
- **Default:** `0`, если элемент отсутствует, — это вне диапазона ограничения, поэтому торговец без этого элемента не платил бы ничего; указывайте элемент явно.
- **Source:** game code (the merchant loader; the dealer-structure union).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/dSellModifier`

- **Type:** `Decimal` (`FLOAT`) — a 32-bit float in game code.
- **Description:** Множитель, применяемый когда торговец продаёт игроку; `1.25` берёт 125% стоимости, `1.0` берёт полную стоимость. У дилера-ремонтника (`ubTypeOfArmsDealer` `3`) в том же месте хранится `dRepairCost`, и значение масштабирует цену ремонта.
- **Numeric semantics:** Загрузчик ограничивает диапазоном `0.1..5.0`; больше — дороже.
- **Values:** `0.1..5.0` после ограничения.
- **Default:** `0`, если элемент отсутствует, — вне диапазона ограничения; указывайте элемент явно.
- **Source:** game code (the merchant loader; the dealer-structure union).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/minCoolness`

- **Type:** `Integer` (`UINT32`)
- **Description:** Нижняя граница, применяемая к вычисленному минимальному `coolness` ассортимента торговца.
- **Numeric semantics:** Загрузчик ограничивает присутствующее значение диапазоном `1..10` (`min(10, max(1, value))`), хотя комментарий структуры по-прежнему говорит `0-10`. Затем значение действует как `max(minCoolness, min(9, computedMin))`.
- **Values:** `1..10`, если элемент присутствует.
- **Default:** `0`, если элемент отсутствует; это ниже диапазона ограничения и оставляет вычисленный минимум неограниченным снизу.
- **Source:** game code (the merchant loader clamp; the coolness calculation).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/maxCoolness`

- **Type:** `Integer` (`UINT32`)
- **Description:** Верхняя граница, применяемая к вычисленному максимальному `coolness` ассортимента торговца.
- **Numeric semantics:** Ограничивается до `1..10`, если присутствует, затем используется как `min(maxCoolness, computedMax)`; после этого игра принудительно делает максимум не меньше минимума плюс один.
- **Values:** `1..10`, если элемент присутствует.
- **Default:** `0`, если элемент отсутствует; это ниже диапазона ограничения и оставляет вычисленный максимум как есть.
- **Source:** game code (the merchant loader clamp; the coolness calculation).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/addToCoolness`

- **Type:** `Integer` (`UINT32`)
- **Description:** Фиксированная величина, добавляемая к обоим концам вычисленного диапазона `coolness` торговца вместе с бонусом торговца от Rebel Command.
- **Numeric semantics:** Больше — лучший ассортимент раньше. Загрузчик `Merchants.xml` сохраняет любое значение `UINT32` без проверки диапазона; предел `0..10` применяется только к `<COOLADD>` в устаревшем блоке `CONTROL` файла `*Inventory.xml`.
- **Values:** `0..10` по замыслу; поставляемая таблица использует `0` и `1`.
- **Default:** `0`, если элемент отсутствует.
- **Source:** game code (the merchant loader; the coolness calculation; the inventory loader for the legacy check).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/coolnessProgressRate`

- **Type:** `Integer` (`UINT32`)
- **Description:** Процент прогресса игрока, задающий `coolness` ассортимента торговца. Игра вычисляет `min = progress * rate / 100` и `max = min + 1`, добавляет `addToCoolness` (плюс бонус Rebel Command) к обоим, ограничивает минимум через `minCoolness` и `9`, а максимум — через `maxCoolness` с принудительным `max >= min + 1`.
- **Numeric semantics:** Процент; больше — быстрее прогресс. Загрузчик `Merchants.xml` не проверяет диапазон — проверка `0..100` относится к `<PROGRESSRATE>` в устаревшем блоке `CONTROL`, — поэтому значение выше `100` выводит `coolness` за пределы диапазона прогресса игрока.
- **Values:** `0..100` процентов по замыслу.
- **Default:** `0`, если элемент отсутствует; тогда оба конца зависят только от `addToCoolness`.
- **Source:** game code (the coolness formula; the merchant loader; the inventory loader for the legacy check).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/dailyIncrement`

- **Type:** `Integer` (`UINT32`) — an integer amount, not a decimal.
- **Description:** Деньги, добавляемые каждый день после удержанной доли: `cash = cash * dailyRetained / 100 + dailyIncrement`, затем ограничиваются значением `dailyMaximum`.
- **Numeric semantics:** Деньги в целых единицах; больше — больше ежедневных денег. В загрузчике `Merchants.xml` ограничения нет (устаревший блок `CONTROL` ограничивает `<INCREMENT>` диапазоном `0..1000000`).
- **Values:** Деньги.
- **Default:** `0`, если элемент отсутствует.
- **Source:** game code (the merchant loader; the daily cash reset).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/dailyMaximum`

- **Type:** `Integer` (`UINT32`) — an integer amount, not a decimal.
- **Description:** Потолок денег, накапливаемых торговцем: после ежедневного обновления деньги снижаются до этого значения, если они выше.
- **Numeric semantics:** Деньги; больше — выше потолок. Поэтому потолок `0` опустошает деньги дилера при каждом ежедневном обновлении.
- **Values:** Деньги.
- **Default:** `0`, если элемент отсутствует, поэтому при отсутствии значения деньги дилера ограничены нулём.
- **Source:** game code (the merchant loader; the daily cash reset).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/dailyRetained`

- **Type:** `Integer` (`UINT32`) — an integer percentage, not a decimal despite the `d` prefix.
- **Description:** Доля текущих денег, которую торговец сохраняет при ежедневном обновлении, в процентах, до добавления `dailyIncrement` и применения `dailyMaximum`.
- **Numeric semantics:** Процент: `100` сохраняет всё, `0` не сохраняет ничего. В загрузчике `Merchants.xml` ограничения нет (устаревший блок `CONTROL` ограничивает `<RETAINED>` диапазоном `0..100`).
- **Values:** `0..100` процентов.
- **Default:** `0`, если элемент отсутствует.
- **Source:** game code (the merchant loader; the daily cash reset).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/daysDelayMin`

- **Type:** `Integer` (`UINT32`) — whole days, not a decimal.
- **Description:** Нижняя граница задержки поставки для дозаказанных предметов; задержка составляет `daysDelayMin + Random(daysDelayMax - daysDelayMin)` дней.
- **Numeric semantics:** Дни; комментарий структуры подразумевает `1..10`, но загрузчик `Merchants.xml` это не проверяет (устаревший блок `CONTROL` ограничивает `<REORDERMINIMUM>` диапазоном `1..10`).
- **Values:** `1..10` по замыслу.
- **Default:** `0`, если элемент отсутствует; при отсутствующем максимуме это даёт задержку в `0` дней.
- **Source:** game code (the merchant loader; the reorder delay).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/daysDelayMax`

- **Type:** `Integer` (`UINT32`) — whole days, not a decimal.
- **Description:** Верхняя граница задержки поставки: игра выбирает `daysDelayMin + Random(daysDelayMax - daysDelayMin)`.
- **Numeric semantics:** Дни; держите значение не меньше `daysDelayMin`, потому что разница вычисляется в беззнаковой арифметике и меньший максимум переходит в огромный случайный диапазон. В загрузчике `Merchants.xml` ограничения нет (устаревший блок `CONTROL` ограничивает `<REORDERMAXIMUM>` диапазоном `1..10`).
- **Values:** `1..10` по замыслу, `>= daysDelayMin`.
- **Default:** `0`, если элемент отсутствует.
- **Source:** game code (the merchant loader; the reorder delay).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/useBRSetting`

- **Type:** `Boolean` (a `bool` in game code).
- **Description:** Если включено, торговец использует настройку качества Bobby Ray's для своего ассортимента. Когда `ubBobbyRayQuality` лучше, чем `BR_GOOD`, максимальный `coolness` торговца повышается на `quality - 1` плюс ещё один для использованных предметов — так же, как обрабатывается собственный магазин Bobby Ray's.
- **Numeric semantics:** Переключатель: загрузчик разбирает целое число через `atol`, поэтому любое ненулевое значение становится истиной, а `0` — ложью.
- **Values:** `0` или `1` в поставляемой таблице.
- **Default:** `0` (false), если элемент отсутствует.
- **Source:** game code (the merchant loader; the suitability check).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/allInventoryAlwaysAvailable`

- **Type:** `Boolean` (a `bool` in game code).
- **Description:** Если включено, каждый предмет считается полностью подходящим для этого дилера (`ITEM_SUITABILITY_HIGH`) независимо от `coolness` или прогресса игрока, поэтому доступен весь каталог, а не только открытый прогрессом. Bobby Ray's исключён из этого упрощения.
- **Numeric semantics:** Переключатель: любое ненулевое значение означает истину.
- **Values:** `0` или `1` в поставляемой таблице.
- **Default:** `0` (false), если элемент отсутствует.
- **Source:** game code (the merchant loader; the suitability check).
- **Confidence:** `source`

### `MERCHANTSLIST/MERCHANT/nonprofile_loyaltyrequired`

- **Type:** `Integer` (`UINT8`)
- **Description:** Лояльность города, необходимая дилеру без профиля в городе, прежде чем он начнёт торговать с игроком.
- **Numeric semantics:** Рейтинг лояльности, сравниваемый с `gTownLoyalty[].ubRating`; больше — строже, `0` — без требований.
- **Values:** `0..255`.
- **Default:** `0`, если элемент отсутствует.
- **Source:** game code (the merchant loader; the loyalty check).
- **Confidence:** `source`

### `INVENTORYLIST/INVENTORY/uiIndex`

- **Type:** `Integer` (`UINT32`) — the loader stores this field as `UINT32`.
- **Description:** Слот строки в массиве инвентаря дилера. Игра просматривает этот массив в порядке слотов, поэтому это позиция строки, а не просто метка.
- **Values:** `0..16000` (`uiIndex < MAXITEMS`, а `MAXITEMS` равно 16001); строка с большим индексом молча отбрасывается.
- **Default:** `0`, если элемент отсутствует, поэтому строка без индекса перезаписывает слот 0.
- **Source:** game code (the inventory loader; the item-count constant).
- **Confidence:** `source`

### `INVENTORYLIST/INVENTORY/sItemIndex`

- **Type:** `Integer` (`INT16`) — the loader stores this field as `INT16`.
- **Description:** ID предмета, который держит дилер. `0` — терминатор списка (`LAST_DEALER_ITEM`), поэтому игра прекращает чтение на первой строке, у которой `sItemIndex` равен `0`; строки в слотах выше этого первого нуля никогда не видны.
- **Values:** ID предметов; `0` завершает список и одновременно является значением «нет предмета».
- **Default:** `0`, если элемент отсутствует; это завершает список на этой строке.
- **Source:** game code (the inventory loader; the inventory lookup).
- **Confidence:** `source`

### `INVENTORYLIST/INVENTORY/ubOptimalNumber`

- **Type:** `Integer` (`UINT8`) — the loader stores this field as `UINT8`.
- **Description:** Количество предмета, которое дилер стремится держать; игра получает значение через `GetMaxItemAmount` и использует его как начальный и максимальный запас предмета.
- **Numeric semantics:** `0` — нет запаса. Значение возвращается через `INT8`, поэтому значение в `128..255` приходит отрицательным и не проходит проверки запаса `> 0` в игре; держите значение на `127` или ниже.
- **Values:** `0..127` пригодны; само поле хранит `0..255`.
- **Default:** `0`, если элемент отсутствует.
- **Source:** game code (the inventory loader; the inventory lookup and its callers).
- **Confidence:** `source`

## Relations

- Инвентарь каждого дилера хранится в отдельном файле, привязанном к дилеру фиксированным именем в коде инициализации игры; строка `Merchants` с совпадающим `uiIndex` задаёт данные торговца этого дилера.
- `sItemIndex` ссылается на [Items](../Items/Items.md), а строки файла читаются в порядке `uiIndex`, пока `sItemIndex` не достигнет `0`.
- `ubShopKeeperID` ссылается на таблицу профилей NPC; `szName` носит информационный характер, и игра его не читает.
- Дилер-ремонтник (`ubTypeOfArmsDealer` `3`) использует `dBuyModifier`/`dSellModifier` как множители скорости и цены ремонта.

## Localization

Отображаемые имена и метки локализуются через языковые оверлеи; числовые ID и коды — нет.

## Versions

В v4 и v5 совпадают пути полей; значения могут различаться.

## Sources

- Данные таблиц: `Merchants.xml` и 80 файлов инвентаря дилеров.
- Игровой код: загрузчик торговцев, загрузчик инвентаря (включая его устаревший блок `CONTROL`), структура дилера и константы флагов, ежедневное обновление денег, задержка дозаказа, логика `coolness` и пригодности, просмотр инвентаря и код инициализации, привязывающий каждый файл к дилеру.
- Имена полей и комментарии XML, включая списки `NPCIDs`, `ubTypeOfArmsDealer` и `uiFlags`, процитированные в начале `Merchants.xml`.
- Каждое поле выше ссылается на код, который его читает; никаких формул сверх этих строк не заявлено.

## Open questions

- `uiFlags`: открытых вопросов не осталось — комментарий XML перечисляет пять битов поведения, и структура дилера определяет те же константы; дополнительные биты классов предметов обычно задаются устаревшим блоком `CONTROL`.
- `coolness`: открытых вопросов не осталось — `min = progress * rate / 100`, `max = min + 1`, `addToCoolness` (плюс бонус торговца от Rebel Command) добавляется к обоим, минимум ограничен `minCoolness` и `9`, а максимум — `maxCoolness` с принудительным `max >= min + 1`.
- Здесь не установлено: должен ли блок `<CONTROL>` в `*Inventory.xml` заменять `Merchants.xml` для своего дилера. Файлы разбираются после `Merchants.xml`, поэтому такой блок перезаписал бы значения дилера, но ни один поставляемый файл его не содержит.
