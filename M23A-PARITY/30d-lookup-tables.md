## Открытые вопросы

1. **Тип `id` lookup-таблиц.** Legacy объявлял `ULong` для `AttachmentClass`, `DrugType`, `ItemFlag`, `AmmoFlag`, `NasAttachmentClass`, `AttachmentPoint`; rewrite объявляет `Integer` для всех, кроме `ItemFlag` (`Raw`). Текущие максимумы ≤ 33554432, кроме `ItemFlag` (8589934592), поэтому потери нет. Нужен ли отдельный 64-битный unsigned тип (или `Raw` для всех «битовых» lookup-id) на будущее — с учётом L-DATA-012?
2. **Inline fallback.** Если в будущей версии `Lookup/X.xml` отсутствует, rewrite даст текстовое поле с ⚠ вместо имён. Нужен ли встроенный fallback (данные legacy устарели) или допустимо считать отсутствие файла дефектом сборки данных?
3. **Пустая/неполная запись lookup.** Должен ли `AddRow` на lookup-таблице сразу создавать `name` и запрещать сохранение записи без него (L-AUX-036), или это должно быть правилом M26a «Lookup CRUD»?
4. **Аллокация id.** Следующий ключ — `int32 max+1` (`TableDocument.cs:143-161`); для `ItemFlag` id > 2^31 игнорируются, а bitmask-таблицы требуют выделения следующего бита, а не максимума. Где это реализовывать — в M26a или в самом generic AddRow?
5. **`AmmoChoices` без потребителя.** В rewrite таблица полезна только как редактируемый файл; legacy использовал её для виртуальной `ENEMYAMMOCHOICES` (M-10). Оставлять ли её в общем списке таблиц или помечать как «только данные игры»?
6. **`ItemFlag` без потребителя.** Таблица заполняется и открывается, но ни одно поле её не использует ни в legacy, ни в rewrite. Это мёртвая таблица или резерв под будущие поля?
7. **Языковые lookup-оверлеи.** `XmlFileLookupRepository` умеет накладывать `Russian.<Lookup>.xml`, но в v4/v5 таких файлов нет и legacy их не поддерживал. Нужна ли эта возможность (имена lookup не локализуются в 1.13) или её следует задокументировать как расширение?
8. **Сортировка combo.** Legacy сортировал значения по имени (по умолчанию), для `ExplosionSize` — по id; rewrite показывает порядок файла и всегда добавляет id в подпись. Восстанавливать ли сортировку для длинных списков (`Silhouette` 56, `AttachmentClass` 36, `ItemFlag` 36)?
9. **Несогласованность `AmmoFlag`.** Файл содержит id 0–4, а данные используют значения 8 и 16 (биты 3 и 4). Это дефект данных 1.13 или id трактуются как битовые индексы? Rewrite сейчас подписывает только id 1, 2, 4, а 8/16 остаются безымянными битами.
10. **`Lookup.NasLayoutClass`.** Rewrite-only таблица (M-17), для поля `nasLayoutClass`, у которого в legacy lookup не было. Оставлять ли её как обычную редактируемую таблицу?
