## Открытые вопросы

1. **Поля заголовка STI.** Legacy читает `ubRedDepth` с 30, `ubGreenDepth` с 31, `ubBlueDepth` с 32, `ubDepth` с 33 и `uiAppDataSize` с 34; rewrite — `Depth` с 30, `RedDepth` с 31, `GreenDepth` с 32, `BlueDepth` с 33 и `AppDataSize` с 48 (`StciParser.cs:102-106`). В проверенных образцах байты 30–33 равны `08 08 08 00`, app-data везде 0, поэтому декодирование и тесты не затронуты. Канонический layout нужно подтвердить до использования этих полей; при `appDataSize > 0` rewrite может неверно вычислить начало палитры.
2. **Поведение legacy при отсутствующих `ubGraphicType`/`ubGraphicNum`.** Rewrite трактует отсутствующий тип как 0 и требует индекс (`ItemWorkspaceViewModel.cs:2351-2369`). Для 351/350 записей без типа (303/302 записи класса Gun, остальные — Launcher, Knife, Ammo и др.) это работает, для 10 записей без индекса превью нет. Фактическое падение legacy на `DBNull` не исполнялось — вывод сделан по типам VB-присваиваний; нужно подтвердить, не заполнял ли `DataSet` значения по умолчанию.
3. **Прозрачность на будущих/модовых STI.** Правило palette-index-0 лучше legacy-эвристики на текущих данных, но rewrite отвергает RGB/не-ETRLE STI (`StciParser.cs:108-121`), а legacy попытался бы их декодировать. В v4/v5 таких файлов нет (1576/1575 проверено, все flags `0x28`, 256 цветов); нужна ли поддержка для будущих версий — вопрос к M24+.
4. **Big-изображение в гриде.** Rewrite заменил нативное big-изображение и высоту строки `GreatestBigImageHeight` на миниатюру 24×24 и строку 22 px. Считать ли это приемлемым UX-упрощением или требуется режим «большие изображения в гриде»?
5. **DI-регистрация imaging.** `AddXmlEditorImaging` (`ImagingServiceCollectionExtensions.cs:24-43`) не вызывается в `App.xaml.cs`; production-путь создаёт каталоги напрямую в `WpfItemImageService.cs:30-39` с кэшем по умолчанию 128 MiB на каталог данных. Это осознанно (сервис — публичный API для потребителей) или регистрацию нужно использовать в приложении, чтобы управлять ёмкостью кэша?
6. **Согласованность с 20-й секцией.** `L-ITEM-013` уже отмечает отсутствие пересчёта `Maximum`; L-IMG-005 добавляет backend-причину. `L-ITEM-014` (нет списка кадров) подтверждён и не дублируется. L-IMG-020 (устаревшие миниатюры) — новое наблюдение; вердикты `20-item-ui.md` не пересматривались.
