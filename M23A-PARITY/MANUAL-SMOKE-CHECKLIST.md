# Ручной smoke-чеклист M23a7

**Назначение:** закрыть подшаг M23a7 аудита паритета ручной проверкой WPF-интерфейса на данных v4 (русская сборка с оверлеями) и v5 (английская базовая сборка). Проверяется фактическое поведение, а не пункты меню. Код в M23a7 не меняется.

**Основание:** `M23A-PARITY-AUDIT-PLAN.md`, раздел «M23a7 — проверка»; `PLAN.md`, разделы M19–M22c и «Проверка»; `LEGACY-PARITY-REPORT.md`, раздел «Проверка M23a7».

**Результат:** заполненная таблица сценариев, подпись и вердикт; итог внесён в `LEGACY-PARITY-REPORT.md`, раздел «Проверка M23a7», подраздел «Результат ручного smoke (2026-11-03)» и дополнение «v5 и ветка S13 (2026-11-06)».

> **Обязательно:** работайте только с временными копиями `Data-1.13`. Не сохраняйте ничего в `References/JA 2 1.13 v4` и `References/JA 2 1.13 v5`: это оригиналы, они должны остаться побайтно неизменными. Неизменённые файлы редактор не должен перезаписывать вообще; это проверяется хешами в S12, S23, S36–S40, S48 и S50.

> **Подготовка (2026-11-03):** `util-scripts\manual-smoke.cmd` создаёт изолированный каталог
> `%USERPROFILE%\XER-manual-smoke`: минимальную копию v4 (`Data-1.13\TableData`, `BigItems`,
> `Interface`, `tilesets\0`), каталог `appdata` с `settings.json` и запускает приложение с
> `XER_APP_DATA`, указывающим на этот `appdata`. Скрипт запускайте из обычного Проводника или
> PowerShell (не из терминала агента). `-Reset` пересоздаёт каталог, `-V5` добавляет копию v5,
> `-NoLaunch` только готовит данные. Пути и подсказки записываются в `README.txt` рабочего каталога.
> Приложение скрипт копирует в `app\`: сборка из песочницы агента может нести метку Low integrity,
> и Windows запускает такой exe с пониженными правами, из-за чего `metadata.sqlite` не создаётся
> (`SQLite Error 14`). Копия, созданная процессом обычного пользователя, этой метки не имеет.

> настроек — теперь `Strings` разрешает ресурсы по явно выбранной культуре (`Strings.SetUiCulture`).

## 1. Подготовка

1. Сборка и тесты (гейты M23a7; записать результаты):
   ```powershell
   dotnet build xml-editor-reloaded/XmlEditorReloaded.slnx -warnaserror
   dotnet test xml-editor-reloaded/XmlEditorReloaded.slnx
   git rev-parse --short HEAD
   ```
   В песочнице агента сборка идёт с `-m:1 --no-restore`, а тесты — через `test.ps1`
   (`AGENTS.md`, раздел «Песочница»).
2. Сделать временные копии данных (в копию входит весь `Data-1.13`, потому что для STI-превью нужны `BigItems`, `Interface`, `tilesets`). Команды — для PowerShell: временный каталог задаётся как `$env:TEMP`; запись `%TEMP%` PowerShell не раскрывает — robocopy примет её буквально и создаст папку `%TEMP%` в текущем каталоге:
   ```powershell
   robocopy "E:\Projects\JA2_1.13 Tools\References\JA 2 1.13 v4\Data-1.13" "$env:TEMP\xer-smoke\v4\Data-1.13" /E
   robocopy "E:\Projects\JA2_1.13 Tools\References\JA 2 1.13 v5\Data-1.13" "$env:TEMP\xer-smoke\v5\Data-1.13" /E
   ```
3. Снять хеши оригиналов и копий до начала проверки. `Get-FileHash` возвращает объекты `FileHashInfo`, а `Set-Content` записывает их строковое представление (имя типа), поэтому в файл пишутся строки `hash  path` — их и сравнивает S50:
   ```powershell
   Get-ChildItem "E:\Projects\JA2_1.13 Tools\References\JA 2 1.13 v4\Data-1.13\TableData","E:\Projects\JA2_1.13 Tools\References\JA 2 1.13 v5\Data-1.13\TableData" -Recurse -File | Get-FileHash -Algorithm SHA256 | Sort-Object Path | ForEach-Object { "{0}  {1}" -f $_.Hash, $_.Path } | Set-Content "$env:TEMP\xer-smoke\orig-before.txt"
   Get-ChildItem "$env:TEMP\xer-smoke\v4\Data-1.13\TableData","$env:TEMP\xer-smoke\v5\Data-1.13\TableData" -Recurse -File | Get-FileHash -Algorithm SHA256 | Sort-Object Path | ForEach-Object { "{0}  {1}" -f $_.Hash, $_.Path } | Set-Content "$env:TEMP\xer-smoke\copy-before.txt"
   ```
4. Запустить приложение:
   ```powershell
   dotnet run --project xml-editor-reloaded/src/XmlEditorReloaded.App
   ```
   Для чистого старта можно предварительно закрыть редактор и переименовать `%AppData%\XmlEditorReloaded\settings.json` и `layouts.json`; это пользовательские настройки, не данные игры.
5. Язык интерфейса — русский (проверка переключения — S44). Если подписи в UI отличаются, фиксируйте фактические.

**Пометки:** `☐` — не выполнено, `✅` — ожидаемое поведение подтверждено, `❌` — дефект или расхождение, `N/A` — сценарий к датасету не применим. Для каждого `❌` в таблице укажите ожидаемое и фактическое поведение, файл/таблицу и шаг. Известные ограничения перечислены в сценариях; они не считаются новыми дефектами, если поведение совпало.

**Куда записывать:** после проверки добавьте в `LEGACY-PARITY-REPORT.md` в раздел «Проверка M23a7» дату, коммит сборки, количество `✅/❌/N/A`, таблицу дефектов и подпись. Новые дефекты идут в реестр пробелов M23b, а не исправляются в M23a7.

## 2. Сценарии

### A. Запуск, датасеты, таблицы и сетка

**S01. Холодный старт.** Запустить без активного каталога (настройки очищены). Ожидаемо: статус «Каталог данных не выбран.», подсказка «Дважды щёлкните таблицу в списке, чтобы открыть её для редактирования.», список таблиц пуст, окно не падает.

**S02. Добавление v4.** «Обзор...» → каталог копии из шага 2 — `%TEMP%\xer-smoke\v4\Data-1.13` (в PowerShell это `$env:TEMP\xer-smoke\v4\Data-1.13`). Ожидаемо: статус «Загружено таблиц: N.», в списке есть `Items.Items`, `Inventory.MercStartingGear`, `NPCInventory.AdditionalDealer_43_Inventory`, `Lookup.AttachmentPoint`; у таблиц с оверлеями колонка «Языки» показывает `ru`, у остальных `—`; «Метаданные» — «Есть»/«Нет»; модальных ошибок нет.

**S03. Добавление и переключение v5 без закрытия вкладок.** Добавить `%TEMP%\xer-smoke\v5\Data-1.13`, открыть в v4 generic-таблицу, переключить активный датасет на v5. Ожидаемо: вкладка v4 остаётся открытой с меткой `JA 2 1.13 v4`; список таблиц меняется на v5; можно открыть вторую вкладку v5 с меткой `JA 2 1.13 v5`; переключение не теряет несохранённые правки и не закрывает вкладки.

**S04. Неверный каталог.** Через «Обзор...» выбрать существующую папку без `TableData` (например, `References\xml-editor`). Ожидаемо: статус «В выбранной папке нет TableData или Data-1.13\TableData.», активный каталог и список таблиц возвращаются к прежнему валидному датасету, приложение отвечает; после выбора корректного каталога список восстанавливается.

**S05. Детали и диагностика таблицы.** Выбрать в v4 `Items.Items`: «Детали» показывает имя, «Записей: 1776», диагностика пуста. Выбрать в v5 `Lookup.AttachmentPoint`: статус «Повреждённый файл» и строки диагностики с кодом и сообщением (ошибка у закрывающего тега в строке 31). Ожидаемо: без исключений и без попытки исправить файл.

**S06. Открытие generic-таблицы.** Двойной щелчок по v4 `Backgrounds`; затем по v5 `Lookup.Cursor`. Ожидаемо: вкладка с названием таблицы и меткой датасета, сетка с колонками и строками, статус «Готово.»; у v4 `Backgrounds` селектор «Язык:» содержит «Базовая» и «Русский», у v5 `Lookup.Cursor` — только «Базовая». Стрелка у правого края сетки скрывает и показывает панель деталей (◀ при скрытой, ▶ при открытой), подсказка меняется на «Показать/Скрыть панель деталей»; при минимальной ширине окна подпись «Язык:» остаётся рядом с combo.

**S07. Поиск в сетке.** В v4 `Items.AttachmentSlots` ввести в «Поиск» часть имени (например, `Laser`, ожидается строка `Laser Attachments`). Ожидаемо: число строк уменьшается, счётчик показывает «Записей: X из 63»; при бессмысленном запросе — «Нет записей по запросу.»; очистка поля возвращает все строки.

**S08. Фильтры.** В `Items.Weapons`: «Фильтр» → «Добавить условие» → колонка `ubWeaponClass`, оператор «равно», значение; добавить второе условие и переключить «Все (И)»/«Любое (ИЛИ)»; проверить сводку «Условий: N». Через контекстное меню ячейки — «Фильтровать по значению» и «Исключить значение»; «Сбросить фильтр» возвращает исходный вид. Ожидаемо: фильтр не меняет XML и не скрывает несохранённые правки.

**S09. Multi-select и массовая правка.** В `Items.Weapons` выделить 3 строки (Ctrl+щелчок), проверить «Выделено строк: 3»; «Данные → Массовая правка…» → выбрать числовую колонку, операцию «Установить» (или «Прибавить»), значение; проверить статусы «Изменено»/«Без изменений» и сводку; «Применить». Ожидаемо: изменены только выделенные строки, кнопки Undo/Redo работают, при отмене значения восстанавливаются; сохранение — только на копии.

**S10. Добавление, дублирование, удаление строки.** На v4 `Lookup.Cursor` (23 строки, ключ `id`): «Добавить запись», задать `id` и `name`; «Дублировать» (новый ключ); «Удалить» с подтверждением «Удалить запись …? Её перевод также будет удалён.»; после каждой операции — Undo/Redo. Проверить составную таблицу (например, `Items.Attachments`): «Дублировать» недоступно с сообщением о неподдерживаемом дублировании. Ожидаемо: нет потери соседних строк, ключи не дублируются, тестовые строки удалены до сохранения.

**S11. Колонки и layout.** В v4 `Items.Weapons`: «Колонки», поиск колонки, снятие/установка флажка, «По умолчанию»/«Все»; изменить ширину/порядок/сортировку; закрыть и снова открыть таблицу — layout сохранился. «Вид → Сбросить раскладку» возвращает defaults. Ожидаемо: `%AppData%\XmlEditorReloaded\layouts.json` обновляется, данные XML не меняются.

**S12. Сохранение грязной вкладки.** В v4 `Lookup.Cursor` изменить `name`. Ожидаемо: «Сохранить» активна только при изменениях; после сохранения статус «Сохранено.», хеш файла изменился. Открыть и закрыть таблицу без правок: хеш и время файла не изменились, кнопка сохранения неактивна; Ctrl+S даёт «Нет изменений для сохранения.». Повторить на v5.

**S13. Закрытие вкладки.** На грязной вкладке нажать `✕`. Ожидаемо: окно «Несохранённые изменения», сообщение «В «…» есть несохранённые изменения.», кнопки «Сохранить»/«Не сохранять»/«Отмена». «Отмена» оставляет вкладку и правки; «Не сохранять» закрывает без записи; «Сохранить» пишет файл и закрывает. Отдельно проверить, что ошибка сохранения оставляет вкладку открытой.

**S14. «Сохранить всё» и закрытие приложения.** Сделать грязными две вкладки (например, `Lookup.Cursor` и `Backgrounds`), нажать «Сохранить всё». Ожидаемо: «Сохранено таблиц: 2.» и обе вкладки чистые. Снова изменить данные и закрыть окно приложения: для каждой грязной вкладки появляется тот же запрос; «Отмена» отменяет закрытие и сохраняет вкладки; «Сохранить» закрывает приложение после записи; чистые вкладки не запрашиваются.

### B. Item workspace

**S19. Подтаблицы item.** У item 12 открыть «Подтаблицы». Известное ограничение: полная class-aware видимость полей ITEM не реализована (`L-ITEM-005`, M23b1).
