# M14.5 — Metadata Verification Report

This report documents how the legacy schema in `References/xml-editor/BackEnd/DatabaseCode.vb` was
turned into verified SQLite metadata for XML Editor Reloaded. `References/` is read-only: the
generator and verification script were one-off tools outside the repository, and only the resulting
migration and this report are committed.

> **Scope note:** this report describes the M14.5 verification pass (46 declaring columns and 502
> hints). Migration `0008_M20AuxiliaryTables.sql` later added the shopkeeper, enemy/militia/IMP,
> drop, merchant, and sound tables (173 tables and 1923 hints in total). Those hints follow the same
> document-driven rules; the M20 corpus tests cover them.

## Method

1. Parsed every `MakeColumn` call in `DatabaseCode.vb`, including the simple `For` loops that expand
   indexed columns, and mapped each legacy table to the `Tables` seed through its
   `TableProperty.FileName`.
2. Loaded every mapped table from both reference data sets (`JA 2 1.13 v4` and `JA 2 1.13 v5`) and
   collected the direct child fields of each record.
3. Kept a field only when it occurs in at least one data set, every non-empty value parses as the
   declared CLR type, and every lookup value resolves in the referenced `Lookup/*.xml` file.
4. Excluded a type when any value failed validation, rather than emitting a metadata guess. No field
   was added to a document; hints never declare absent fields.
5. Imported only real `Lookup/*.xml` references. Legacy references to main tables (`ITEM`, `AMMO`,
   `ITEMTOEXPLOSIVE`, and similar) use their own value/text columns and filters, so they are not
   represented as lookup files in this milestone.

Stale fields are concentrated in `Inventory.MercStartingGear` (325 indexed fields replaced by the
nested `GEARKIT` structure) and `Items.Items` (53 indexed/nested fields). The `Items.Items` stale set
includes `AvailableAttachmentPoint0..9`, `DefaultAttachment0..9`, and the indexed
`FlatBase1..3`/`Percent*1..3` modifier fields; the actual data uses single
`AvailableAttachmentPoint`/`DefaultAttachment` fields and nested `STAND_MODIFIERS`,
`CROUCH_MODIFIERS`, and `PRONE_MODIFIERS`.

Fields without a legacy definition are mostly structural (`Items.Pockets` capacity dictionary fields,
`Items.Drugs` nested effect lists, `Inventory.MercStartingGear.GEARKIT`) plus five `Items.Items`
fields: `AvailableAttachmentPoint`, `DefaultAttachment`, and the three nested modifier elements. The
two single-value attachment fields were added manually with verified types; nested elements remain
read-only and are detected by the schema builder.

The eight mask fields are `usItemClass`, `AttachmentClass`, `nasAttachmentClass`,
`nasLayoutClass`, `AvailableAttachmentPoint`, `AttachmentPoint`, `DrugType`, and
`usActionItemFlag`. The three Items lookup fields are `ubCursor` (`Lookup.Cursor`), `Inseparable`

`Columns` is populated only for lookup tables, whose `id`/`name` shape is fixed. `Lookup.ItemFlag.id`
is declared as `Raw` because its IDs reach `8589934592`; the other lookup ids are `Integer`.
Every other table stays on non-declaring hints, so sparse records are not expanded.

## Consequences

- `TableValidator` now validates present fields through hints and reports `invalid_type` and
  `lookup_missing` warnings on real data without false positives.
- `TableRecord.SetFieldValue` uses the same hints, so a backend edit cannot write `abc` into an
  integer-typed field even if the UI validation is bypassed.
- `LookupEntry.Id` is a `long`, and `XmlFileLookupRepository` parses 64-bit lookup IDs.
- M15 added named bit labels from the verified lookup masks, and a migration now maps 11 flag fields
  to their lookup files. The remaining metadata gap is main-table lookup sources; the metadata
  needed for ordinary `Lookup/*.xml` combos is in place.

`validation.invalid_type` or `validation.lookup_missing` warnings on either data set. The existing
corpus no-rewrite checks remain green.
